# Deployment Guide — Energy Patterns Web Explorer

This guide explains how to publish the web application to [Vercel](https://vercel.com).

The web app lives in the `web/` subdirectory of this repository. Vercel is configured to use `web/` as its root, so **you do not need to build locally** — Vercel builds and deploys automatically whenever you push to GitHub.

---

## Prerequisites

- The repository must be on GitHub (or GitLab/Bitbucket).
- You need a [Vercel account](https://vercel.com/signup) (free tier is sufficient).

---

## First-Time Setup

### 1. Push the repository to GitHub

If you have not done this yet:

```bash
git remote add origin https://github.com/<your-username>/<repo-name>.git
git push -u origin main
```

---

### 2. Import the project in Vercel

1. Go to [vercel.com/new](https://vercel.com/new).
2. Click **Import Git Repository**.
3. Authorise Vercel to access your GitHub account and select this repository.

---

### 3. Configure the Root Directory

> **This is the critical step.** The web app is not at the repo root — it is in `web/`.

In the **Configure Project** screen:

| Setting | Value |
|---------|-------|
| **Root Directory** | `web` |
| **Framework Preset** | Next.js (auto-detected) |
| **Build Command** | `npm run build` (default) |
| **Output Directory** | `.next` (default) |
| **Install Command** | `npm install` (default) |

Click the pencil icon next to **Root Directory**, type `web`, and confirm.

---

### 4. Configure Environment Variables

In the Vercel dashboard → your project → **Settings** → **Environment Variables**, add:

| Variable | Example value | Required |
|----------|--------------|---------|
| `NEXT_PUBLIC_SUPABASE_URL` | `https://xxxx.supabase.co` | Only if using Supabase features |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | `eyJ...` | Only if using Supabase features |

If you are not using Supabase yet, skip these. The site builds and runs without them.

See `web/.env.example` for a full list of all supported variables.

> **Never commit `.env.local`** — it is gitignored. Always use Vercel's environment variable UI for secrets.

---

### 5. Deploy

Click **Deploy**. Vercel will:

1. Clone the full repository.
2. `cd` into `web/`.
3. Run `npm install`.
4. Run `npm run build` (`next build`).
5. Deploy the `.next/` output as a serverless application.

The first deploy takes about 1–3 minutes.

---

## Automatic Deploys on Push

After the first setup, every `git push` to the `main` branch triggers a new deploy automatically. No manual steps needed.

```bash
# Edit something, commit, push → Vercel deploys
git add .
git commit -m "Update diagnostic page"
git push
```

Preview deploys are also created for every pull request branch.

---

## What Must Be Committed to Git

The Vercel build runs from the **committed state of the repository**. Files that are gitignored will not be available during the build.

### ✅ Must be committed

| Path | Why |
|------|-----|
| `web/src/content/*.json` | Manifest files read at build time by Server Components |
| `figures/ep_structure/*.png` | Composite figures served via `/api/figures` route |
| `figures/cluster/**/*.png` | Cluster analysis figures (if they exist) |
| `results/ep_structure/composite_stats.json` | Stats generated by `step5`; read by the extraction script |

### ❌ Must NOT be committed

| Path | Why |
|------|-----|
| `web/.env.local` | Contains secrets — use Vercel env vars instead |
| `web/node_modules/` | Installed by Vercel automatically |
| `web/.next/` | Built by Vercel automatically |
| ERA5 NetCDF files in `data/` | Too large for git; not needed at build time |

## How Figures Are Served

Figures are **not** inside `web/public/` — they live in the repository root (`figures/`, `docs/`, etc.). The web app serves them via the API route:

```
GET /api/figures?path=figures/ep_structure/composite_egr.png
```

This route is defined in `web/src/app/api/figures/route.ts`. It reads the file from the filesystem relative to the repository root using `process.cwd()/..`.

**On Vercel**, `process.cwd()` is the `web/` directory (the Root Directory), so `..` resolves to the repository root — exactly where the figures are committed.

**Security**: The route only allows files under `figures/`, `docs/`, `results/`, and `data/`. Path traversal is blocked.

## Generating Assets Before Committing

The web manifests and composite figures must exist in the repository **before** pushing for Vercel to include them in the build.

### Full pipeline to prepare a deploy

```bash
# 1. Run the scientific pipeline (if needed)
cd scripts/ep_structure_analysis
python step4_create_figures.py     # → figures/ep_structure/composite_*.png
python step5_update_scientific_notes.py --no-pdf  # → results/ep_structure/composite_stats.json

# 2. Run the web extraction script
cd ../..
python scripts/web/build_site_manifest.py
python scripts/web/extract_cluster_site_data.py
python scripts/web/extract_composite_site_data.py   # reads step5's JSON output

# 3. Commit everything
git add figures/ep_structure/ results/ep_structure/ web/src/content/
git commit -m "Update composite figures and web manifests"
git push
```

Vercel will auto-deploy after the push.

## When Do You Need a Local Build?

You **do not need** to run `npm run build` locally for a deploy to work. Just push the committed assets and Vercel handles the build.

Run `npm run build` locally **only** when:
- Debugging TypeScript compilation errors.
- Checking that a page generates correctly before pushing.
- Verifying that no `readManifest` calls crash due to missing JSON files.

---

## Verifying a Deploy

1. Go to your project page on Vercel.
2. Click the latest deployment.
3. Check **Build Logs** for any errors.
4. Click **Visit** to open the deployed site.
5. Navigate to `/analyses/composites/egr` — if composite figures are committed, they should appear.

If a page shows a placeholder instead of a figure, check:
- Is `figures/ep_structure/composite_egr.png` committed and pushed?
- Is `web/src/content/composite_figures_manifest.json` committed?
- Does `composite_figures_manifest.json` show `"exists": true` for that diagnostic?

---

## Redeploy Without Changes

To trigger a redeploy (e.g., to pick up a Vercel config change):

1. Go to Vercel → Deployments.
2. Click the **⋯** menu on the latest deployment.
3. Click **Redeploy**.

Or push an empty commit:

```bash
git commit --allow-empty -m "trigger redeploy"
git push
```

---

## Checking Build Logs

In the Vercel dashboard:

1. Go to **Deployments**.
2. Click a deployment.
3. Click **Build Logs** to see the full Next.js build output.
4. Click **Runtime Logs** to see server-side errors at runtime (API route calls, etc.).

## Coexistence with the Scientific Pipeline

The scientific Python pipeline is completely independent of the web deploy. You can:

- Run Python scripts and commit outputs without touching `web/`.
- Update the web app without touching Python scripts.

The flow is:

```
Python scripts (step4, step5)
    → figures/ep_structure/*.png
    → results/ep_structure/composite_stats.json
        ↓
scripts/web/extract_composite_site_data.py
    → web/src/content/composite_*.json
        ↓
git push
    → Vercel auto-build → deployed site
```

PDFs continue to be generated by `step5` independently of the web deploy.

## Limitations and Known Constraints

| Limitation | Solution adopted |
|-----------|-----------------|
| Figures are gitignored by default (`figures/**/*.png`) | Added explicit exception for `figures/ep_structure/*.png` in `.gitignore` |
| ERA5 NetCDF files are too large for git | Not needed at build time; stats are pre-computed by `step5` → JSON |
| `web/src/content/*.json` manifests are gitignored by default | These must be committed; the gitignore exception `!web/src/content/*.json` was **not** added — commit them explicitly |
| Vercel free tier has a 100MB source size limit | ERA5 data is not committed; figures are PNGs ≤ 300 DPI, typically a few MB each |

> **Note on `web/src/content/*.json`**: These manifest files are small and are committed to git. They are generated by running the web extraction scripts (see pipeline below) and must be present for the Vercel build. The `.gitignore` does **not** exclude them.

## Local Development

```bash
# Install dependencies (once)
cd web
npm install

# Start local dev server
npm run dev
# → http://localhost:3000

# Lint
npm run lint

# TypeScript check
npm run typecheck
```

For local development, the `/api/figures` route serves files from the filesystem directly — no build step required for figures to appear, as long as they exist on disk.
